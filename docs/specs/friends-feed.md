# The friends feed

**Status: shipped in 2.2.0** ([#562](https://github.com/itsmemeworks/adhx/pull/562)) and extended since (reactions, sends, the reactions feed). This is the living contract; read it before changing who sees what.

ADHX is a private feed of the best of every social network, picked by your closest friends and family. Each server is one group of people. This spec is the shared contract for the work that turns a pile of personal saves into that group's feed. Read it before changing anything below.

## The rule: named to friends, never to strangers

- A **member** is a signed-in, non-banned account on this server. Everyone who can sign in is one group (one group per server, no circles).
- **Saves are shared with members by default.** A save can be marked **private**: it is still kept, searchable and playable by its owner, but no other member sees it, counts it or is told who saved it.
- **Members see who saved what.** Savers are named (username, display name, avatar, when) to other members.
- **Strangers never see names.** Signed-out visitors, public pages (`/now` signed out, `/moments/*` signed out, previews, public channels, the public tweet JSON, trending, OG images, the sitemap) keep the old behaviour: savers are counted, never named, and private saves are never counted.
- Existing saves join the shared feed on upgrade (they default to not private). The web app shows a one-time notice explaining this, with a link to make saves private.
- Saves with `source = 'quoted'` (the quoted post stored with a save) are never shown as someone's save.
- **Notes on saves** follow the same rule: members see a saver's note next to their face; strangers never do, and a private save's note reaches its owner only.

## Data

- `bookmarks.is_private integer NOT NULL DEFAULT 0`: a guarded ALTER in `migrate.ts`, the Drizzle column `isPrivate` in `schema.ts`, and the same column in `FULL_SCHEMA_SQL` in `src/__tests__/api/setup.ts`.
- `phone_save_queue.is_private integer NOT NULL DEFAULT 0`, so a private share from a phone stays private.
- `bookmarks.note text NULL`: the saver's note ("making this Sunday"). Cleaned by `cleanNote` (`src/lib/people/note-text.ts`): whitespace collapsed, control and direction characters dropped, ends trimmed, at most 140 characters (grapheme clusters, so an emoji counts as one); empty → null. A guarded ALTER in `migrate.ts`, `note` in `schema.ts` and in `FULL_SCHEMA_SQL`. Clones of a public channel never copy it.
- `phone_save_queue.note text NULL`: the note sent with a queued share (cleaned; `''` clears a repeat save's note, null leaves it).
- `post_views (user_id, platform, post_id, seen_at)`, primary key `(user_id, platform, post_id)`: the server-side watched list. It is user-linked, so it needs an `ACCOUNT_GUARDS` entry and a delete on account clear and delete.
- `keep_jobs.progress integer NULL`: the download percent the keep worker last wrote (in steps of 5, cleared on each claim), so "Getting it ready · 62%" survives the in-memory progress. A guarded ALTER in `migrate.ts`, `progress` in `schema.ts` and in `FULL_SCHEMA_SQL`.
- `post_sends (from_user_id, to_user_id, platform, post_id, note, created_at, seen_at)`, primary key `(from_user_id, to_user_id, platform, post_id)`: "send straight to your people". `seen_at` is set when the recipient sees the post (`markSeen`). Both user columns are account-guarded; account delete and clear remove every row to or from the account. DDL in `src/lib/sends/schema-sql.ts` (shared by `migrate.ts` and `FULL_SCHEMA_SQL`), Drizzle `postSends`.
- `moment_alert_subs (user_id, forming_id, created_at)` (primary key `(user_id, forming_id)`) and `moment_alerts (id, user_id, slug, title, created_at, seen_at)`: "Tell me when it's live". Same DDL file; both account-guarded and cleared with the account.
- `invites (id, token_hash, created_by, created_at, expires_at, used_by, used_at, revoked_at, name_hint)`: single-use invite links. `id` is the public handle for listing and revoking; `revoked_at` lets a revoked link say so. Also user-linked.

## Shared helpers (server)

- `src/lib/people/savers.ts`
  - `type Saver = { username: string; name: string | null; avatarUrl: string | null; savedAt: string; isYou: boolean; note?: string }` (`note` only when they left one)
  - `saversFor(keys: { platform: string; id: string }[], viewerId: string): Map<string, Saver[]>`, keyed by `platform:id`.
    - Includes non-banned members' saves that are not private, plus the viewer's own save even when it is private.
    - Excludes `source = 'quoted'` rows.
    - Ordered newest saver first.
    - Returns an empty map when `viewerId` is `''` (signed out).
    - Each saver carries their `note`. Since others' private saves are never included, a private save's note only ever reaches its owner. Everything built on `saversFor`/`withSavers` (feed, blend, search, similar, channel queues, moment items, phone posts, the live poll's `saverUpdates`, `/doing`) carries notes; faces that stand for more than one post (moment cards, group channel cards) and watchers/reactions never do.
- `src/lib/bookmarks/note.ts`: `noteOption(body)` (a request's `note`), `setSaveNote(userId, platform, id, note)`, `applyRepeatNote`, and `clearPostNotes(platform, id, username?)` for admins.
  - `visibleSaveFilter`: the SQL condition "not private and not quoted and saver not banned". Every query that counts or groups other people's saves (moments, trending, Everyone search `publishable`, group channels, the blended feed) must use it, so a post with only private savers never surfaces.
- `src/lib/people/members.ts`: `listMembers(viewerId)` returns members with their visible save counts, for friend channels and the feed's per-friend controls.

## API additions (web)

All of these require sign-in unless marked public.

- `POST /api/bookmarks/add` and `POST /api/tweets/add` accept `private?: boolean`. A repeat save that passes `private` updates the flag.
- `PATCH /api/bookmarks/[id]/private` with body `{ platform, private }` → `{ private }`.
- `POST /api/bookmarks/add`, `POST /api/tweets/add` and `POST /api/app/save` (sync and queued) accept `note?: string`. A new save stores it (cleaned); a repeat save with `note` replaces it (`""` or `null` clears it); without `note` it is left alone.
- `PATCH /api/bookmarks/[id]/note` with body `{ platform, note }` (`note`: string or null; empty clears) → `{ note }` (as stored, or null). 400 without a string or null; 404 when it isn't your save. Only ever writes your own row.
- Moderation: `POST /api/admin/posts { platform, id, clearNotes: true | "<username>" }` (admins) clears every note on the post, or one member's, writes an `admin_audit` `clear_note` row and returns `{ platform, id, notesCleared }`. It does not hide the post.
- `FeedItem.savers?: Saver[]` and `FeedItem.isPrivate?: boolean` (the viewer's own save is private). These are set on `/api/feed`, `/api/search`, `/api/search/similar` (signed in), channel queues and moment items, but only when the viewer is signed in.
- `GET /api/search?scope=everyone`, signed in: the same posts as today, minus posts whose only savers are private, with `savers` attached. Signed-out callers keep the anonymous shape.
- `GET /api/feed/blend?mode=new|everyone|friends|mine&types=video,photo,text,article&limit&cursor` → `{ items: FeedItem[], nextCursor: string | null, caughtUp: boolean, nothingYet: boolean, total: number, types: FeedKind[], waiting: { [kind]: number } }`
  - `types` ("What's in your feed") filters by kind: `video` (sound, such as SoundCloud, counts as video), `photo`, `text`, `article`, judged the same way as `toPhonePost` and search's type filter (an article first, then video, then photos, else text). Omitted, it's the person's stored choice (`user_preferences` `feed.types`), else `video,photo`. `caughtUp`, `why` and `total` apply within it. In `new`, `waiting` counts the unseen posts it leaves out, by kind.
  - Items carry `savers`, `isPrivate`, `why` (the headline reason) and `whyReasons: { kind, text, username? }[]` (every reason, headline first; `kind` is `together | more | like | close | fresh | yours`).
  - `new` returns only posts someone else saved in the last 14 days that the viewer hasn't seen (no `post_views` row), blended, newest-weighted, and ends with `caughtUp: true`. Posts only the viewer saved are left out (they know them). `nothingYet` is true when nobody else saved anything in that window, so the client can say "Nothing new yet" instead of "caught up".
  - `everyone` blends all members' saves; the viewer's own play sparingly (×0.3, at most one in every four); seen posts are down-weighted (×0.35). A quiet server reaches past 14 days to the newest 300 posts.
  - `friends` is what friends saved that the viewer hasn't saved themselves.
  - `mine` is the viewer's saves (newest 500, not archived).
  - `limit` 1–50 (default 20). The cursor is opaque: the first page computes a snapshot (kept per user for about 5 minutes under a seed the cursor carries), so later pages never reshuffle. An expired snapshot is recomputed from the same seed; New then starts over from what's still unseen.
- `GET /api/feed/types` → `{ types }` and `PUT { types: FeedKind[] }` (at least one) → `{ types }`.
- `GET /api/feed/weights` → `{ weights: { username: -1 | 1 } }` and `PUT { username, weight: -1 | 0 | 1 }` → `{ weights }` ("Show more / less from …", `user_preferences` key `feed.weights`). Only other members.
- `POST /api/views` with body `{ posts: [{ platform, id }] }` (at most 50) marks posts seen → 204. Idempotent: a post keeps the time it was first seen. Rows older than 180 days are pruned at migrate.
- `GET /api/channels` adds `group: [{ slug, name, size, members, savers, newCount, covers }]` (made from everyone's visible saves; `members` = how many saved into it, `savers` = up to 3 faces) and `friends: [{ username, name, avatarUrl, size, newCount, covers }]` (one per other member with visible saves; `newCount` = their visible saves you haven't saved or seen), plus `canInvite`.
- `GET /api/channels/group/[slug]` and `GET /api/channels/friend/[username]` return play queues in the `/api/channels/auto/[slug]` shape (`{ name, items, total, understood, close, refined, nextOffset }`), newest save first. Each item carries `isNew: boolean`: not in your saves and not seen (`post_views`), the same reading as `newCount` (`newKeysFor` in `src/lib/feed/views.ts`). The friend queue adds `friend` and `note` (their latest note on a save other members may see, `{ text, platform, id, savedAt }`, or null; never a note on a private or quoted save, skipping posts gone upstream; `friendNote` in `src/lib/channels/friends.ts`) and takes `?new=1` (only what's new to you); your own username is 404 (your saves are My saves).
- `group_channels (slug, name, size, post_keys, savers, position, saves_at_compute, computed_at, model_version)`: server-wide, no `user_id`. Recomputed when missing, the model changed, after 12 h, after ±10 visible saves, or when a counted saver left or was banned. Every read re-checks each post's visible savers.
- Moments: when signed in, `MomentView.recentSaves` and `MomentView.windowMinutes` ("LIVE · 3 saves in 10 min"): the visible saves into the moment's posts in the last hour, counted over the smallest of 5, 10, 15, 30 or 60 minutes that holds the oldest of them, in whole minutes (`recentOf` in `src/lib/moments/people.ts`; none → `0` and `60`). Private saves never count, not even the viewer's own. Members' stream events carry them too. Also when signed in, `MomentView.savers` (up to 5 faces plus `people`, saves inside the moment's window, newest first), `MomentView.watchers`, moment items carry `savers` (on the item, not the post), the detail carries `watchers`, the stream's `watching` event carries `watchers: Saver[]` (members tuned in now, without the receiver and banned accounts, names only to signed-in subscribers) and `save` carries `saver` (who just saved it). Moments name visible saves only: a private save is never counted or named there, not even to its owner. Names are computed per request from the moment's post keys (`momentPostKeys` + `saversFor`); the engine and anything it broadcasts stay anonymous. Signed out, every moments response keeps its old shape (no `savers` or `watchers` keys).
- `POST /api/moments/{slug}/react` with body `{ emoji, platform, id }` or `{ text, platform, id }` (exactly one) → `{ id, at }`. `emoji` is one of 😂 🔥 😭 👀 💀 ❤️; `text` has whitespace collapsed, control and direction characters dropped, ends trimmed, and must then be 1–40 characters (an emoji counts as one); it is only ever rendered as text, never HTML. 20 reactions a minute per person, 6 of them words; never stored, only counted for admins (`reaction_counts`: member, day, kind; see `docs/specs/admin.md`). It reaches the signed-in subscribers watching that moment (the sender included, with `isYou`) as a `reaction` event `{ slug, id, at, saver, emoji | text, post: { platform, id } }`. Strangers never receive one. Errors: `bad_reaction`, `bad_text`, `bad_post`, `busy` (429), `no_moment` (404).
- `POST /api/invites` (admin, or any member when Who can invite isn't "Only me") → `{ id, url, expiresAt }`. `GET /api/invites` lists unused ones (with a short `code` from the id, never the link); `DELETE /api/invites/[id]` revokes one; `POST /api/invites/[id]/link` gives a fresh link for it (the old one stops working).
- Who can invite: `admin | approve | anyone` (`PATCH /api/people { inviteMode }`, admins; `INVITES=members` is only the first default). With `approve`, someone a member invited is `pending` (signed out everywhere but `/invite/waiting` and `GET /api/auth/approval`) until an admin answers `POST /api/people/requests/[id] { decision: approve | not_now | decline }`. `GET /api/people` → `{ members, isAdmin, canInvite, inviteMode, requests? }`; phone: `GET /api/app/people`, `POST /api/app/people/requests/[id]`.
- `GET /api/activity/processing?scope=all|mine|needs` (phone: `GET /api/app/doing`): posts on their way, stuck or just finished, only ones the viewer may see, with `savers`, step, status, reason and retry. A running download's percent is the live one, else `keep_jobs.progress`. `POST /api/activity/processing/retry` and `/link-only` `{ platform, id }` for people who saved it.
- `GET /api/activity/processing/posts?posts=platform:id,…` (at most 20; 400 above) → `{ posts: [{ platform, id, state, step, percent, keptAt }], people: [{ username, name, avatarUrl }] }`: is each post kept yet, for the theater's "Getting it ready" (`src/lib/processing/keep-status.ts`). `state` is `waiting` (a download queued, or a save from the last 30 minutes the worker hasn't picked up), `keeping` (downloading; `percent` 0–99 when known) or `converting` (making it play everywhere), with `step` 2 or 3, else `kept` (`keptAt` = when the copy finished) or `none` (nothing to wait a moment for: keeping is off, the download is waiting out a retry or gave up, the disk is full, or the Mac helper that converts is away). Posts the viewer may not see (`seenBy`) are left out. `people` is up to 4 of the viewer's people (never the viewer), most recent saver first, for "Shared with your people".
- **Send straight to your people** (`src/lib/sends/`): `GET /api/posts/send?platform=&id=` → `{ sendable, people: [{ username, name, avatarUrl, has, sent }] }` (every other member; `has` = they have a shared save of it (a Just for me save is never revealed, so that person can be sent it); `sent` = you already sent it to them). `{ sendable: false, people: [] }` when the only save you can see is your own private one; 404 `not_found` when you can't see any save (someone else's private save doesn't count; moderated posts are not found). `POST /api/posts/send { platform, id, to: [username] (1–20), note? }` → `{ sent: [username], skipped: [{ username, reason: has | sent | unknown }] }` (`unknown`: not another member, banned or waiting; 403 `private` for your own private-only post; 60 a minute, 429 `busy` with `Retry-After`). The note is cleaned like a save note.
- In New, an unseen send leads (newest send first, even when the post is older than 14 days or you saw it before it was sent) with the reason `{ kind: 'sent', text: 'Pete sent you this', username: 'pete' }` (two senders: "Pete and Ana sent you this"; plus `note` when there is one), until you see it. With a note, Pete's `Saver` on the item carries it as `note`. In Everyone/Friends it is the headline reason but keeps its place; Mine never says it. A sent post shows whatever "What's in your feed" is set to (a text post sent to someone who only watches videos still reaches them).
- The `like` reason adds `post: { platform, id, posterUrl }`: your own kept post it's most like (`posterUrl` is the feed's cover address, a path from the server root, or null).
- **Forming moments**: signed in, each `FormingView` (snapshot `forming[]`, stream `snapshot` and `save` events) adds `people: [{ username, name, avatarUrl }]` (up to 4 members whose visible saves made the group, newest first; never a private save) and `alert: boolean`. Signed out, neither key is sent. Forming ids carry a per-process part (`f<boot>-<n>`), so a stored bell never lands on a different group after a restart.
- `PUT|DELETE /api/moments/forming/{id}/alert` → `{ alert }` (404 `forming_gone`). `GET /api/moments/alerts` → `{ alerts: [{ id: 'a1', slug, title, at }] }` (unseen, newest first, at most 20, 24 hours); `POST /api/moments/alerts/seen { ids }` → `{ ok: true }` (your own only). A bell survives merges and the 5-minute regroup: the engine moves it to the forming group holding most of its posts (`reconcileForming`), fires one alert per subscriber when the group goes live (promoted, or absorbed by a regroup's moment), and drops it silently when the group dissolves (`src/lib/moments/alerts.ts`).
- **Keep this channel** on a From everyone channel: `POST /api/channels/group/{slug}/keep` → `{ tag, url, added }`. The tag is the channel's name without apostrophes, sanitised ("Food you'll cook one day" → `food-youll-cook`). Posts you haven't saved are saved for you first from a member's visible save (`source = 'channel_keep'`, not private, no note copied); posts already at 5 tags are skipped; the channel isn't made public. `GET /api/channels/group/{slug}` adds `kept: { tag, url } | null` (you have a channel with that tag).
- `/invite/[token]` (public page): pick a name, which signs you in, then shows the phone pairing code and QR on the same screen. A used or expired invite says so.

## Phone API additions (`/api/app/*`, phone key)

- `PhonePost.savers: Saver[]` and `PhonePost.isPrivate: boolean`.
- `POST /api/app/save` accepts `private: boolean` (in the async queue too).
- `POST /api/app/private` with body `{ platform, id, private }` → `{ private }`.
- `POST /api/app/save` accepts `note` (in the async queue too); `POST /api/app/note` with body `{ platform, id, note }` → `{ note }` (404 `not_saved`). `PhonePost.savers[].note` as above.
- `GET /api/app/feed?mode=new|everyone|friends|mine&types&cursor&limit` → `{ items: PhonePost[], nextCursor, caughtUp, nothingYet, total, types, waiting, hidden }`; each item adds `why` and `whyReasons`. `types` as on the web; `hidden` repeats `waiting` under the name the phone apps read.
- `mode=lineup` (the phones' New, also accepted by `/api/feed/blend`): Just saved since you last looked, Not seen yet, then For you, always in that order (`lineup()` in `src/lib/feed/blend.ts`). Each item adds `section`; the page adds `sections: { just, unseen, foryou }`. See `docs/specs/phone-app.md` → The friends feed on the phone.
- `GET|PUT /api/app/feed/types`: the same stored choice as `/api/feed/types`.
- `GET /api/app/feed/weights` → `{ weights: { username: -1 | 1 } }` and `PUT { username, weight: -1 | 0 | 1 }` → `{ weights }`: the same stored "Show less / Show more from …" as `/api/feed/weights` (400 `bad_weight`, 404 `no_member` for yourself or no such member).
- `POST /api/app/seen` with body `{ posts: [{ platform, id }] }` → 204.
- `GET /api/app/search?scope=mine|everyone`.
- `GET /api/app/channels` → `{ group, friends, mine }`, using the shapes above with covers as absolute-path URLs. `mine` = your channels then Made for you, `{ slug, name, size, kind: 'channel' | 'made-for-you', isPublic, covers }`. `GET /api/app/channels/{group|friend|mine}/{slug}` → `{ items: PhonePost[] }` (`friend` takes `?new=1`; `mine` tries your channel first, then Made for you). On `group` and `friend` each item adds `isNew: boolean` (as on the web); `friend` adds `note` (`{ text, platform, id, savedAt }` or null). These also accept a signed-in session.
- `GET /api/app/live` → the moments snapshot with `savers`, `watchers`, `recentSaves` and `windowMinutes` on each moment, covers as image addresses (a path from the server root, or a full URL for a link's preview picture), the Just saved strip as `PhonePost`s. `GET /api/app/live/{slug}` → `{ moment, items: PhonePost[], watchers }` (404 `moment_gone`).
- `GET /api/app/send?platform=&id=` and `POST /api/app/send` (same bodies and rules as `/api/posts/send`). The phone New feed carries the `sent` reason and the like reason's `post` as on the web.
- `/api/app/live` `forming[]` entries add `people` and `alert`; `PUT|DELETE /api/app/live/forming/{id}/alert` → `{ alert }` (404 `forming_gone`); `GET /api/app/alerts` → `{ alerts }` and `POST /api/app/alerts/seen { ids }` → `{ ok: true }`.
- `POST /api/app/channels/group/{slug}/keep` → `{ tag, url, added }`; `GET /api/app/channels/group/{slug}` adds `kept`.
- `POST /api/app/live/{slug}/react` (same body and rules as the web) and `GET /api/app/live/{slug}/stream`: SSE for that moment only (`watching`, `save` with `item.post` as a `PhonePost`, `formed`, `reaction`), counting the phone's member as watching by name.

## Product behaviour

- **Saver faces**: up to 3 overlapping avatars plus "Ana and Ben saved this" or "Ana and 3 others", on the theater byline, search tiles, channel tiles and phone players. Your own save shows as "You". Tapping a face opens that friend's channel.
- **Private toggle**: "Just for me" in the theater's Save sheet and More menu, the phone share cards and the phone player's More sheet. A private post shows a small lock.
- **New**: the signed-in home (`/` → `/play?feed=new`, first tab in the nav). It plays only what you haven't seen, then ends on a card: "You're all caught up. Go touch grass." and "That's everything your people saved since you last looked.", with Browse channels, See what's live and Watch it all again (Everyone, seen posts included). A post counts as seen after 2 s on stage, or when you skip it. Everyone · Friends only · Mine switches the mode (New lights Everyone). Next to it, **What's in your feed** shows a summary ("Videos and photos") and opens four toggle chips (Videos, Photos, Text posts, Articles; at least one stays on); videos and photos by default. When the filter holds back unseen posts, the caught-up card adds "4 text posts waiting · Show them", which plays just those, this once (`/play?feed=new&types=text`). On a server where nobody else has saved anything lately: "Nothing new yet. Save something for your people to find." with Paste.
- **The blend**: the signals are fresh, saved together, close to you, like what you keep, not seen yet, variety (no more than 2 in a row from one friend, or from one Made for you topic) and your own (sparingly). Each item carries `why` ("Ana and Ben saved this", "Like the frog videos you kept", "Mum saved this · 1h", "You watch most of Ben's saves"), shown as the chip at the stage's top-left ("Saved together" for two or more savers) and on each Up next tile. **Why this one** (in More) lists every reason, with Show more / Show less per friend.
- **Channels**: a "From everyone" row (group channels: "Rabbit holes, dug by your friends", "38 saves · 3 of you", "N new") and a "Your people" row (one big avatar card per friend, "N new", plus "Invite someone" → Settings when you may invite) above "Made for you" and "Your channels". A friend's channel is `/channels/friend/{username}` (members only): Play all, Play the N new ones, "New" on each tile you haven't saved or seen (the queue's `isNew`), and their latest note as a paper tile ("Ana's note", the quote, "on Charlie bit my finger · 3 days ago", linking to that post in their channel) when they have one, "Only people on this server can see this page." Play: `/play?group=slug`, `/play?friend=username[&new=1]`.
- **Getting it ready** (board j1-4): when the post on the theater's stage is still on its way to this ADHX (`waiting`, `keeping` or `converting` above; members only, not on text or article stages), the stage waits instead of playing: the post's poster blurred with a light sweeping across it, a ring with the real percent (turning without a number when there's none), "Getting it ready…", "Your ADHX is keeping a copy. It'll be here in a moment." and a checklist (Got the link ✓ · Keeping a copy · Making it play everywhere). The theater asks when a post comes on stage and every 1.5 s while it waits, and plays the moment it's kept (a load that failed while it waited starts again, `POST_KEPT`). While it waits, a save of yours that isn't private shows "Shared with your people" with their faces at the top-left. A post seen being kept, or kept in the last two minutes, shows "Kept on your ADHX" (j1-5). The sweep and spin are `animate-nx-*`, so reduced motion stills them.
- **Live time span**: the Right now lead card says "LIVE · 3 saves in 10 min" for members (`recentSaves`/`windowMinutes`), and keeps "5 people · 26 saves" when there's no figure.
- **Send straight to your people** (board j4-4): the theater's Share sheet ends with "Or straight to your people": an optional note and a Gob-shaped face per member (`SendToPeople`). Tapping one sends and ticks it; someone who already has it is dimmed, with "Jo already has it." Your own private-only post says "Just for you. Share it first to send it." The recipient's chip reads "Pete sent you this" with Pete's face (`WhyLead`).
- **Forming moments** (j7-1): forming cards show the faces saving them and a "Tell me when it's live" button that toggles ("We'll tell you"); turning it on asks the browser for notification permission inside the click. Any signed-in page polls `/api/moments/alerts` every minute (`MomentAlerts` in AppShell) and shows "Kitchen synths is live · Tune in", plus a browser notification when allowed; dismissing, tuning in or 15 s on screen marks it seen.
- **Why this one**: the like reason has a 38 px Gob-shaped thumbnail of the kept post at its right (`LikeThumb`), opening it in My saves.
- **Keep this channel** (j6-2): a From everyone channel's side panel has Keep this channel, then "Kept · Open" (to `/t/{you}/{tag}`).
- **Who saved it**: the theater's faces open a popover listing each saver and when, with their note in quotes under their name, and "See Ana’s saves" (yours: "See your saves" → My saves).
- **Notes**: "Add a note" in the theater's Save sheet and the phone share card (140 characters, a counter from 120). ### Reactions playback reliability

The web Reactions player follows `nextOffset` until the source is exhausted,
keeps the API's full total, coalesces page requests and rejects late pages from
an earlier queue. A selected post beyond the first page still opens first.
Temporary page failures retain the offset for retry before recommendations or
an end card. Post start keys use the shared network ID rules (including
SoundCloud's `~` IDs). Opening the original-post or Share sheet holds the current
video; closing resumes only a video that was playing in the same queue and post.
